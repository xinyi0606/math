## 1. 输入与不可变边界

| 输入 | 用途 | 加载规则 |
|---|---|---|
| `data/raw/附件1.xlsx` | Q1单日价格、负荷、光伏预测；Q2/Q3固定日型价格 | 只读；144列按官方模板列序映射，不平移 |
| `data/raw/附件2.xlsx` | 全年负荷与光伏实际值 | 只读；365天×144个10分钟步；实际值只用于执行核算或已过去日期的训练 |
| `data/raw/附件3.xlsx` | 每日00:00、06:00、12:00、18:00光伏预测 | 日期向下填充仅在内存完成；整点节点分段线性插值；每次仅更新未执行后缀 |
| `data/raw/附件4.xlsx` | Q4全年波动电价 | 当前及过去价格可用；同日未来真实价格仅允许进入oracle和事后结算 |
| `data/templates/result*.xlsx` | 五个官方结果工作簿 | 复制后填值；工作表名、行列、日期和格式不重排 |

数据审计结论为 `ready_with_warnings`，且没有需要修复的缺失、重复或非法数值，因此不制造内容相同的清洗副本。统一加载器必须验证形状、日期顺序、有限值、非负值与144步长度。

## 2. 统一物理优化内核

每个10分钟步以电量建模，`DT_HOURS=1/6`。连续LP变量为计划或调整购电量 $g_t$、充电量 $c_t$、放电量 $d_t$；光伏富余通过不等式隐式弃用：

$$g_t+d_t-c_t\ge \widehat l_t-\widehat v_t.$$

储能状态满足：

$$E_{t+1}=E_t+0.9c_t-d_t/0.9,$$

并施加 $1200\le E_t\le10800$、$0\le c_t,d_t\le5000/6$。Q1强制日末等于日初；Q2—Q4逐日把日末状态传给次日，仅在12月31日强制全年末为6000 kWh。每次求解后审计平衡、SOC、终端和同时充放电；若同时充放电计数非零，则该轮结果判失败并要求升级MILP，不静默接受。

首轮全年实验采用“一日滚动时域”：每天只执行当日可知预测对应的LP，状态跨日继承，非最终日不人为重置SOC。该实现满足已冻结的跨日连续和全年末约束，但没有为次日及更远期设置显式终端价值；因此终端价值/多日时域列为下一轮敏感性，而不能把首轮结果宣称为完整随机全年问题的理论全局最优。

## 3. Q1实现

- **M1基线**：储能不动作，购电覆盖正净负荷。
- **M2主模型**：144步连续LP，目标为实际日型价格下的计划购电费；强制日末SOC等于6000 kWh。
- **M3交叉验证**：同一144步数据上做SOC网格动态规划，网格依次取400、200、100、50 kWh，报告费用相对M2的差距和收敛趋势。
- **正式输出**：`result1.xlsx`、逐时完整表、约束审计、费用指标和调度图。

## 4. Q2实现

三种预测均在每日00:00生成，任何特征只来自严格早于目标日的数据：

- M1：前一日同槽净负荷；
- M2：过去7日同槽净负荷均值；
- M3：昨日同槽、过去7日均值、日内正余弦和星期特征的 `HistGradientBoostingRegressor`。首轮主配置为 `max_iter=30`、`max_depth=4`、`random_state=2026`，逐日使用目标日前最近30日（早期使用全部可得日）重新拟合。该窗口同时保持严格非前视并控制334次滚动训练的计算量；30/60日与更深模型列入参数敏感性。

每个候选使用相同LP内核和实际执行口径。计划动作固定后，实际净负荷超过计划供能的部分计为紧急购电；计划购电按正常价、紧急量按5倍价结算。比较全年总费用、紧急量、欠预测95%分位、RMSE、MAE和极端日。

## 5. Q3实现

Q3复用Q2-M3的日前净负荷预测。为利用附件3更新光伏，定义日前负荷预测为“Q2净负荷预测 + 00:00光伏预测”；随后以最新光伏预测替换光伏部分，避免再次拟合一个口径不一致的负荷模型。

- M1：只执行00:00计划；
- M2：06:00、12:00、18:00用最新点预测重算剩余后缀；
- M3：在M2结构上，从目标日之前的历史同发布时间误差估计90%光伏高估分位，并从预测中扣除非负安全裕度。

每次更新冻结已执行前缀，并从更新时刻SOC继续求解。调整后的总购电量只与00:00原计划比较一次。下调退款、上调增购和紧急购电严格按冻结公式事后结算。M1—M3在同一负荷预测、状态初值和实际轨迹上比较。

## 6. Q4实现

Q4仅替换价格，预测、物理约束和结算口径继承Q2/Q3：

- M1为波动价无储能基线；
- M2读取当天完整真实价格，只标记为完全信息oracle；
- M3在00:00只使用此前历史日的价格轨迹构造7个情景；06:00、12:00、18:00时，可用当天已实现价格前缀从历史日中选取前缀距离最近的7个情景，但不得读取当天未来真实价格。共同决策最小化情景最坏费用。

Q4-2执行Q2式日前策略；Q4-3执行Q3式滚动与调整。实际价格只用于到时结算、已实现前缀条件化和oracle。报告全年实际费用、最坏日费用、相对oracle机会损失、紧急购电、情景覆盖和保守性。

## 8. 输出矩阵

每问写入 `results/Qx/experiments/round1/`：

- `figures/`：至少一幅核心诊断图；
- `tables/`：官方结果工作簿、逐日指标、完整调度压缩表；
- `metrics/metrics.json`：关键指标、单位和候选角色；
- `logs/run.log`：时间、解释器、参数和完成状态；
- `run_summary.json`：状态、运行时、输入校验、方法、输出路径和审计结果。

根目录 `output/` 另保存五个官方命名工作簿，供最终提交核对。所有随机过程固定 `SEED=2026`。

## 9. 自动验证与失败条件

1. 原始Excel的SHA-256必须与 `data/manifest.sha256` 一致。
2. 每个预测的训练日与特征日必须严格早于目标日；Q4情景索引必须小于目标日。
3. 所有LP必须返回成功状态；任一NaN、负购电、SOC越界、功率越界或平衡残差超过 $10^{-6}$ kWh即失败。
4. 逐时同时充放电数量必须为0；否则不生成“正式可行”结论。
5. Q1终端与Q2—Q4全年终端误差不超过 $10^{-5}$ kWh。
6. 官方模板工作表名、行列数、日期和时段标签与原模板一致；单文件小于5 MB。
7. 正式结果生成后由代码审查逐问核对变量语义、约束方向、时间索引、单位、结果口径和可复现性。

## 10. 首轮解释边界

- Q1-M2可以解释为已冻结连续线性模型的全局最优解，但只有互斥审计通过后才可解释为物理可执行。
- Q2/Q3/Q4为严格非前视滚动策略的样本外回放，不是拥有未来随机量的确定性全年oracle。
- Q3-M3和Q4-M3只是优先进入正式实验；若全年综合费用或保守性不满足人工作答中的回退条件，必须保留M2对照并重新校准，而不能选择性忽略不利结果。
